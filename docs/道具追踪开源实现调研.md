# 道具追踪开源实现调研

调研日期：2026-09-17。本页保留最初源码调研结论；后续已独立实现并实测 Linux 原生 `spec_goto` / `spec_pos` 后端，详见 [原生自动追雷交付与验证](原生自动追雷交付与验证.md)。未运行下载的 HOT/HLAE 代码或注入游戏。

结论：已有实际 CS2 追雷实现。本项目上一轮只实现了协议客户端和调度基础，缺少真实游戏后端；不能把这等同于追雷技术不可实现。

## 1. HOT 的 HLAE 分支：实际追雷代码

仓库为 `papesgit/advancedfx` 的 **hot 分支**，不是 main 分支。本次查询 hot 指向 `686f34deced15a3dbf278f823f9a0afc954e63bc`。

- [NadeCam.cpp](https://github.com/papesgit/advancedfx/blob/686f34deced15a3dbf278f823f9a0afc954e63bc/AfxHookSource2/NadeCam.cpp)
- [NadeCam.h](https://github.com/papesgit/advancedfx/blob/686f34deced15a3dbf278f823f9a0afc954e63bc/AfxHookSource2/NadeCam.h)
- [HOT v0.2.2 发布说明](https://github.com/papesgit/hot/releases/tag/v0.2.2)：已加入跟随手雷镜头，投掷时按住 Alt。

源码中的实际控制命令为 `mirv_nadecam start`、`mirv_nadecam stop`，另有 `radius` 和 `scaninterval` 参数。这些是定制 HLAE 的命令，不是原生 CS2 控制台能力。

实现路径：

1. `IsGrenadeEntity()` 用实体类名等信息识别投掷物。
2. `ScanWorldForGrenades()` 遍历客户端实体，在被观战选手附近搜索。
3. `AcquireGrenade()` 选择范围内距离最近的手雷，保存实体索引并锁定本次获取；默认检测半径 50 个游戏单位。
4. `Update()` 每帧读取实际坐标，从位置差估计运动方向，将镜头放在手雷后方并朝向手雷；平滑方向、位置和角度，低速时调整拍摄方向。
5. 跟踪实体消失时保留最后镜头位置和角度；关闭时可恢复原先观战对象。

与本项目要求仍有差距：

- 没有按击杀来源确定投掷物；多人靠近同时投雷时，最近距离匹配可能选错。
- 控制命令没有指定实体/投掷实例参数，需要新增确定性目标接口。
- 跟踪主要保存实体索引；严谨实现需验证句柄序列号，防止索引复用。
- 实体消失后的静止镜头不等于确认爆炸命中或火区覆盖；需补充作用区域与受害者验证。
- 必须在道具仍处于检测范围时启用。当前 Project Replay 按击杀窗口减 setup 的准备规则不足以保证这一点；需要独立的投掷时间、跟随准备时间，或允许直接指定已在飞行的实体。

## 2. HOT：与双路延迟回放直接相关

[HOT v0.4.0](https://github.com/papesgit/hot/releases/tag/v0.4.0) 已加入较快实例发布击杀、延迟 CSTV 客户端自动切镜头和 vMix 标记。

本次读取提交 `00185f37302ae13dd877bfd82a954c61ebfe8260` 下的：

- [ReplayDirectorClient.cs](https://github.com/papesgit/hot/blob/00185f37302ae13dd877bfd82a954c61ebfe8260/HlaeObsTools/Services/ReplayDirector/ReplayDirectorClient.cs)
- [HotLinkGameClock.cs](https://github.com/papesgit/hot/blob/00185f37302ae13dd877bfd82a954c61ebfe8260/HlaeObsTools/Services/HotLink/HotLinkGameClock.cs)
- [HotLinkPublisher.cs](https://github.com/papesgit/hot/blob/00185f37302ae13dd877bfd82a954c61ebfe8260/HlaeObsTools/Services/HotLink/HotLinkPublisher.cs)

其调度每 50ms 检查候选，使用本地估算游戏时间提前切镜头、设置切镜头锁定窗口，并请求回放标记。`SwitchToKillAsync()` 实际发送 `spectate_slot`，目标仍是击杀者；候选还会过滤非存活攻击者。因此不能直接认为它已实现“道具致死自动追具体那颗雷”，尤其是投掷者死亡后的雷杀。

## 3. demoinfocs-golang：补充事件和道具数据

[项目仓库](https://github.com/markus-wa/demoinfocs-golang) 和 [类型文档](https://pkg.go.dev/github.com/markus-wa/demoinfocs-golang/v6/pkg/demoinfocs/common) 提供道具实体、位置/轨迹、投掷者和火区对象。读取的 `events.go` 中包含 `Kill.Weapon`、`GrenadeProjectileThrow`、`GrenadeProjectileDestroy`、`InfernoStart` 等。

适合补齐击杀来源与投掷生命周期，不负责驱动游戏镜头。仍需验证本项目可获得的实时数据源及延迟；独立解析器生成的实例 ID 不能假设天然跨 A/B 两次解析一致。应固定经过样本测试的库版本，不能因文档存在就宣称所有字段在当前 GOTV 流中可靠。

## 平台和许可证事实

- [HLAE 构建文档](https://github.com/papesgit/advancedfx/blob/hot/BUILDING.md)使用 Windows/Visual Studio，游戏侧为 DLL hook；当前 Linux 原生 CS2 Worker 无法直接加载。调研时未找到可直接替换的 Linux 后端；后续已用原生控制台实现已知轨迹跟随。跨平台 Go 编译成功不代表 HLAE 可在 Linux 游戏进程运行。
- [HOT 使用说明](https://github.com/papesgit/hot)要求定制 HOT-HLAE，官方 HLAE 不能直接代替；其启动示例包含 `-insecure`。实测应使用专用观战/回放实例，并遵守 HLAE 对受保护服务器的使用限制。
- [papesgit/advancedfx hot LICENSE](https://github.com/papesgit/advancedfx/blob/hot/LICENSE) 是 MIT；README 另注明子模块不在同一许可证覆盖范围。
- [HOT README](https://github.com/papesgit/hot)说明 v0.2.2 及以前为 GPLv3，v0.2.3 起改为 source-available。不能把当前 HOT 全部当作宽松许可代码直接复制。本轮没有把第三方源码加入本项目。

## 最初针对 HLAE 的接入建议（现采用原生轨迹方案）

1. 用与 CS2 版本匹配的 HOT-HLAE，在 Windows 专用观战实例验证 `mirv_nadecam start/stop`，先证明画面可控。
2. 扩展追雷控制接口，支持投掷者 + 精确道具句柄/实例；反馈真实目标、镜头和生命周期阶段，接入现有 Worker 协议。
3. 补充投掷时刻与 A/B 游戏时间映射，镜头跟随可早于最终两秒输出窗口；冲突调度按实际占用区间计算。
4. 连接击杀来源和投掷生命周期，完成“识别道具击杀 → B 路跟随目标道具 → 保留结果区域 → 两秒裁剪”。
5. 如要求在 B 路直接追踪实时实体句柄，仍需实体访问能力。若 A 路已提供轨迹且时间已校准，可以使用现在的 native 后端，无需 hook 或 tracking_url。
