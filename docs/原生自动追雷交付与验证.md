# 原生自动追雷交付与验证

2026-09-17：已实现并在本机真实 CS2 + OBS 上录制验证。Linux 后端不需要 HLAE、DLL 注入或独立 tracking bridge。在线 GOTV 尚未验收：当前会话没有提供真实在线源地址。

## 已交付

- `replay-source`：使用 demoinfocs-golang **v5.2.0** 解析 `.dem`、持续增长的 Demo 文件或 CSTV+ HTTP 广播；输出 JSONL 或直接提交 `/api/events`。
- 击杀武器、投掷者、投掷 tick、投掷物实例、轨迹、HE 爆炸和火区关联。实例 ID 包含稳定的 source-id、出生 tick 和实体编号，防止实体编号复用。多人同时投雷不会仅凭最近距离选雷。
- 燃烧弹直接撞击与 `inferno` 烧死分开处理；后一种定位到同一投掷者、受害者附近的唯一火区。火区/撞击空间关联是近似几何判定，歧义不自动发布。
- `tracking_mode=native`：通过持久 NetCon 连接发送 `spec_goto`，目标更新频率 30Hz；等待渲染帧后用 `spec_pos` 回读，核验实际位置和角度。投掷物消失后保留结果区域镜头。火区从解析到的受害者眼位朝向对应火焰区域，避免通用高位镜头进入室内墙顶。
- 同一实例任务合并、轨迹冲突拒绝、远程时钟偏移转换、缺失轨迹/反馈过期/错误镜头/epoch 失效拒绝。轨迹不向未知飞行时段外推。
- OBS 异步开始和停止的等待：实际开始后确认录制；编码器结束后再裁剪，避免读到仍在写入的短文件。
- `event_source=parser` 时，GSI 保留状态信息，停止重复生成击杀数差分候选。

## 启动与配置

发行包含主程序及 `replay-source`（Windows 为 `.exe`）。原生后端在录制机设置：

```json
{
  "mode": "live",
  "event_source": "parser",
  "tracking_mode": "native",
  "netcon": "127.0.0.1:2121",
  "obs_url": "ws://127.0.0.1:4466",
  "strict": false,
  "guard": 0.25,
  "setup": 2
}
```

以上是设置项示例，不是完整 `/api/config` 请求；从网页修改或在完整现有配置上覆盖。OBS 端口以实际配置为准。已有专用会话应填写它的 `session_lock`，防止多个录制程序同时接管。远程模式下导播端也选 `native` 用于轨迹规划，录制机单独配置 NetCon、OBS 和凭据。

设置比赛、地图后，保存配置会更新 epoch；将这个 epoch 传给事件源。先完成 A/B 时间校准，确认误差不超过 guard，再启用采集。严格模式依然阻止出片：本次解决了道具镜头，未实现击杀到视频帧的严格对齐。

先离线检查源数据：

```sh
./replay-source -demo /path/match.dem \
  -source-id match01-feedA -match match01 -epoch 2 > events.jsonl
```

接入持续增长的 A 路 Demo：

```sh
./replay-source -demo /path/live.dem -tail \
  -source-id match01-feedA -match match01 -epoch 2 \
  -from-tick 123456 \
  -wall-anchor <B路对应源游戏时间零点的Unix毫秒> \
  -uncertainty 0.15 \
  -api http://127.0.0.1:7788
```

`-from-tick` 填当前校准点附近的实际 server tick，用于跳过旧事件；解析器仍从文件头建立实体状态。文件被截短会退出；更换文件或开始新比赛应使用新的 source-id 和 epoch。历史文件默认只导出，不会把旧击杀伪装成当前事件。

`-wall-anchor = B路该事件预计发生的Unix毫秒 - 离线导出中该事件的time`。映射同时作用于击杀和每个轨迹点。导播与远程录制机的系统时钟差由现有 remote-sync 再转换。不能把源 tick、源游戏毫秒、A 路接收时间和 B 路系统时间混为一谈。

使用 CSTV+ 时，将 `-demo ... -tail` 替换为 `-cstv https://实际广播地址/`。这是 HTTP 广播地址，**不是**普通 GOTV `host:port`；后者由 CS2 自身连接。`-arrival-delay 8s` 可替代固定 anchor，用实时收到事件的时间加人工测定延迟，仅适用于 tail/CSTV；缓冲与网络抖动会影响精度，必须先滤掉历史积压，并把实测误差计入 uncertainty。不能与 `-wall-anchor` 同时使用。

## 使用边界

1. 原生后端沿 A 路已测轨迹控制 B 路镜头，回读确认的是**镜头位置和角度**，不是 B 路投掷物实体句柄。必须保证两路比赛、地图与时间映射一致；两端内部 epoch 自动转换，无需手动对齐。暂停、回档、重连或延迟变化后重新校准。
2. 实测是播放真实 Demo 的 CS2，不是在线 GOTV。`spec_pos` 在部分服务器上可能受命令权限限制；后端不会开启 `sv_cheats`，回读受限会明确失败。本次本地 Demo 探测曾使用允许该命令的设置，不能据此保证所有在线服务器可用。
3. 目标频率 30Hz，实际频率受游戏帧率和 NetCon 延迟限制；每阶段保存首尾回读，不能证明所有视频帧都正确。位置容差 4 单位、角度 2 度、样本新鲜度 500ms。
4. 没有地图碰撞网格或画面遮挡识别。实体轨迹外侧的摄影机可能遇到墙体、烟雾等；火区已有测得眼位可改善构图，但不是全地图自动避障的保证。素材仍由导播预览后决定是否播出。
5. 需要覆盖完整 `击杀前1秒 + 后1秒 + 两侧guard` 的已知轨迹。飞行采样间隔超过 250ms、起点太晚、身份不唯一、火区位置冲突都不会降级成投掷者视角。

源码参考见 [开源调研](道具追踪开源实现调研.md)。本实现未复制 HOT/HLAE 源码；解析器及依赖许可证随发行包提供。
