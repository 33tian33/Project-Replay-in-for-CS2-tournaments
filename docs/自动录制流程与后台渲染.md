# 自动录制流程与后台渲染

本次调整取代旧方案中的手动 epoch 对齐、整条流水线串行占用与切人后等待 GSI 才开始录制。

## 直接连接，无需配对

Windows 只填 Linux 节点 URL。导播台、录制任务、素材下载、GSI 和网页输出均不要求 token；已移除登录页、配对字段和 replay-source 的 `-token-file` 参数。旧版数据目录的 access-token 文件在程序启动时删除，旧配置字段在保存时清除。旧 GSI 配置中的 auth 字段会被忽略。OBS WebSocket 自身的密码仍按 OBS 设置填写。服务监听范围内的主机可直接控制节点。

## 自动发送

默认 live 模式、自动采集开启。Windows 收到 A 路 GSI 击杀变化后，在下一次调度周期（约 50ms）发送回合号、阶段与剩余秒数，不等手工校准、tick、槽位映射或完整录制方案。Linux 按 B 路 GSI 时钟规划，同人连杀优先，时间连续的同回合击杀合并为一次 OBS 录制，跨玩家在同一任务内直接切镜，无法兼顾的冲突窗口择优。保存配置与重启不再把自动采集强制暂停；手工暂停会保留。首次升级时，旧版已配置节点且开启自动采集的 demo 配置迁移到 live；此后手动选择 demo 仍表示模拟演示，不发送真实击杀。

Linux 可接收多条不冲突的待录任务。镜头与 OBS 仅在实际采集阶段互斥，停止录制并确认落盘后释放；FFmpeg 裁剪、校验、下载回 Windows 不再阻塞下一次录制。冲突计算包括启动提前量，避免两条纸面不重叠的任务在设备启动阶段相撞。

确定的 HTTP 4xx 拒绝只标记该任务失败，不再暂停整条采集。通信故障造成提交结果未知时仍按同一任务 ID 对账，无法确认才暂停，避免重复录制。

## 不需要同步 epoch

两端比赛名称需一致。地图由各端主路 GSI 自动识别，无需手动填写；Windows A 路先换图时，新地图事件最多等待 Linux B 路 120 秒，超时明确失败，不使用事件强制修改 Linux 地图。回合事件接收时自动归入节点本地 epoch；Windows 素材归属保留本地版本。设置页面不再要求输入目标 epoch。

内部版本仍用于防止旧队列在回档、换图后执行。GSI 断流或回档会使旧事件失效。普通 GSI 击杀不依赖两台电脑的系统时间差，也不依赖人工 A/B 延迟校准。旧版解析器绝对时间与道具轨迹路径继续保留自己的校准要求。

## 回合 + 局内时间，无需 tick

普通击杀采用统一回合号、`phase_countdowns.phase`、`phase_countdowns.phase_ends_in`。正常进行中的回合按 `map.round + 1`；进入 over 后锁定此前回合号，避免已完成回合计数提前递增。直到下一回合开始，保枪击杀仍属于刚结束的回合。冷启动在 over 阶段时使用已完成回合计数（至少为 1），不再无条件加一。第三项可能是字符串，需解析为剩余秒数。区分 live、bomb、over 三个阶段，避免下包导致倒计时重置后匹配错误。计数变化恰逢阶段切换时，优先用上一条有效阶段时钟外推事件时刻，给 B 路提前开始录制的机会。后续 over 击杀还携带切换前的时钟锚点及到该击杀的间隔；B 尚在上一阶段时也能提前准备，不等待 over 首帧后才开始规划。Demo 解析按 RoundStart / RoundFreezetimeEnd 锁定回合，RoundEnd 后的击杀不递增回合号。

例如 A 路第 8 回合 live 剩余 45.2 秒击杀，B 路第 8 回合 live 还剩 52.2 秒，Linux 预计 7 秒后出现击杀，并据此安排击杀前 1 秒、后 0.5 秒。B 路尚未进入目标回合时先排队；已越过目标窗口则标记错过。回合号不同的时钟绝不直接相减。

需要 B 路确实落后 A 路。相同时间播放的两个客户端无法在收到击杀后补录此前一秒。GSI 不提供倒计时、Demo 暂停或断流时明确显示等待 / 失败，不编造 tick 或拿系统时间冒充局内时间。

槽位映射可以留空：优先使用显式槽位，否则用 B 路新鲜 roster 中该 SteamID 的唯一、安全玩家名执行 `spec_player`，随后核验 GSI SteamID。同名、纯数字或含控制符的名字仍需已确认槽位，不把 observer_slot 当作命令槽位。

自动化端到端测试覆盖无 tick、无校准、无映射、不同 epoch 的 GSI → HTTP 发送 → 模拟 NetCon / OBS → 素材回传。其中单击杀回传测试的编码器和视频为测试替身；连续 A→B→A 切镜测试使用模拟 OBS/NetCon/GSI 和实际 FFmpeg 裁切视频。另用真实 Demo 验证结算后击杀的回合归属。这些测试不等同于真实 Windows 比赛画面验收。

## 切人即录

提前建立 OBS 连接并检查空闲；清理重复 HUD、回读确认原生游戏 UI 隐藏，发送直接切人命令后，立即请求 StartRecord，不再等下一次 GSI 才开始。保护窗口开始时必须收到切人后的正确目标反馈，录制期间持续检查，错人素材不发布。录制流程不发送 demo_pause，不做录制预热或固定停顿。

一个连续任务最多 30 秒，不跨回合；同一玩家持续观察，相近异地击杀按时间使用 `spec_player` 直接跳到目标，不发送 `spec_next` / `spec_prev`。切换预算至少 200 ms，密集切换时裁去片段中属于其他玩家或切换确认阶段的画面，至少保留击杀前 250 ms、后 150 ms。默认保护量 200 ms、切换预算 200 ms 时，不同玩家击杀间隔至少 1 秒；来不及切换时保留优先路线。同人连杀无需该切换间隔。

默认启动提前量由 2 秒降为 0.2 秒、额外切换间隔由 2 秒降为 0；旧配置的这组默认值自动迁移。启动提前量是设备命令与编码器响应的预算，不是切人后的等待。OBS 实际启动仍有耗时，慢设备可增大提前量。

道具镜头保留必要的位置/关联核验，不把错误道具画面发布为成功素材。双路 Demo 联调的定位暂停和 A/B 延迟启动仅用于建立测试时间差，与正常击杀录制不同。

仍可能跳过：窗口冲突、到达太晚、GSI 合并多次击杀无法逐次定位、缺少 / 停滞的倒计时、玩家名重复或切人确认失败、设备故障。不承诺每次击杀都能录到。

## Windows Workshop Tools 切窗冻结

CS2 的控制台变量原始导出包含三项相关机制：

- `engine_no_focus_sleep`：失焦休眠。
- `fps_max_tools`：Tools 模式在其他窗口获得焦点时的额外帧率上限。
- `r_always_render_all_windows`：强制引擎和工具窗口渲染，标记为 developmentonly，当前构建不一定允许修改。

来源：[CS2 ConVar 原始导出](https://cs2.poggu.me/dumped-data/convar-list/)。这是冻结原因的排查方向，尚未在用户 Windows 上确认根因。单纯帧率上限通常表现为降帧，完全冻结还需区分渲染停止、Demo 暂停和 OBS 捕获冻结。

将发行包 `configs/replay_background.cfg` 复制到 `game/csgo/cfg`，在 Workshop Tools 的游戏控制台执行：

```text
exec replay_background
```

等价命令：

```text
engine_no_focus_sleep 0
fps_max_tools 0
r_always_render_all_windows 1
```

逐项输入变量名回读当前值。若第三项提示 Unknown command 或不可修改，不视为修复成功，不通过 sv_cheats 绕过权限。保持窗口化或无边框且未最小化，切到其他窗口，核验游戏帧、Demo 时间和 OBS 预览是否继续变化。若游戏本身继续而 OBS 冻结，再检查捕获源；若切回后 Demo 时间也未前进，再查暂停状态。`fps_max_ui` 是菜单帧率限制，不能替代 Tools 后台设置。
