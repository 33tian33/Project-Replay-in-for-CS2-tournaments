# Project Replay 0.1.0 交付与测试报告

日期：2026-09-16。环境：Linux aarch64，Go 1.27.1。未修改或启动现有 CSStudio、CS2、OBS 服务。

## 构建产物

Windows x64 便携 EXE/ZIP、Linux ARM64 和 x64 tar.gz 均在 `dist`。`SHA256SUMS` 四个文件校验全部通过。Windows 文件经检查为 x86-64 PE32+；Linux 两个文件分别为静态 ARM aarch64 和 x86-64 ELF。本机执行发布版 ARM64 程序 `-version` 成功。

## 自动化测试

`REPLAY_MEDIA_TEST=1 go test -race -count=1 -v ./...`：15 个顶层测试、10 个子场景通过，没有检测到数据竞争。`go vet ./...` 与 `node --check internal/replay/web/app.js` 通过。

覆盖 OBS 模拟服务的认证和请求、同人双杀/跨人冲突、保护量/切换预算、手动指定冲突、已提交任务保留、旧 epoch、未知身份、误差/迟到/严格模式阻断。100 组随机事件与全子集穷举结果对照，且打乱输入顺序不影响选择。

覆盖 HTTP 直接访问与跨站拦截、OBS 密码隐藏、无登录入口、事件更新幂等、重启恢复、同一数据目录互斥、完整演示出片、ffprobe 两秒媒体检查、HTTP Range、断点下载、损坏文件拒绝发布、GSI +2 不虚构独立事件、重复任务不重录。

两个独立 Service 实例通过实际回环 HTTP 完成时钟同步、Agent 接单、演示出片、导播下载与 SHA-256 校验。另有空数组兼容性与冲突原因保留的回归测试。

## 浏览器实测

实际操作本地导播台：直接打开 → 演示一轮 → 双杀视角被选中 → 两段素材 READY → 预览 → 加入待播。视频元素报告 `readyState=4`、`duration=2`、`videoWidth=960`、`videoHeight=540`。已修复检查中发现的空事件列表导致界面误报离线问题。

## 验收边界

未在 Windows 或 Linux x64 实机运行，未连接真实 GOTV，未执行真实 OBS 录制或 Windows 节目切换。本次只有 ARM64 主机。

尚无 Demo/CSTV+ 精确事件解析、自动游戏时间线校准、逐帧击杀定位。严格模式默认阻止实时精确出片；接受近似定位后可联调已实现的 GSI/NetCon/OBS/FFmpeg 链路。界面是浏览器本地 UI；原子 JSON 快照与 HTTP 轮询、单媒体源人工播出等首版取舍见 README。

这些结果证明首版的软件流程与协议可运行，不等同于规划中的真实赛事 V1 验收。现场联调需要 A/B GOTV 地址、已确认 B 路身份映射、双方实测时间差和 Windows OBS 配置。
