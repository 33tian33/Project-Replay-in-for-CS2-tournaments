# Project Replay 0.1.1 修复与升级

## 更新方法

退出两端旧 Replay 程序。将新版程序放在原程序目录，保留原 `replay-data`；或用 `-data` 指定原数据目录。Windows、Linux 必须同时更新，以使用新增接口和冻结时间字段。不会自动覆盖或清空旧配置，也不会自动重启游戏、Steam、OBS。

1. Windows 填写初始 CT / T 战队名称、图标，点击「保存并同步 Linux」。允许保存比赛过程中展示设置，不递增录制 epoch。图标随配置持久保存。后台节点同步会重试战队信息同步。
2. Linux 将 OBS 切到实际录制场景，点击「安装战队 HUD 到 OBS」。可反复点击，不重复创建输入源；显示比分、计时和按回合换边后的战队名称/图标。OBS 需有 browser_source 插件及 WebSocket。手动安装地址：`http://127.0.0.1:7788/hud.html`，源尺寸 1920×1080，再按画布等比缩放。
3. 两端任务完成后，Windows 点击「两端启用紧凑录制间隔」。旧自定义间隔不会在升级时被悄悄覆盖。默认保护 0.2 秒、准备 0.2 秒、额外间隔 0 秒；配置误差较大时自动增加保护量。
4. 清理时停止 Demo / 回放、等待录制和回传完成，再点击「一键清理两端 Replay 临时文件」。删除操作前有范围确认。先 Linux 后 Windows，失败显示实际结果并允许重试。

## 已确认的问题及修改

- 原生 HUD 原先只写 TCP，不读取游戏执行结果。现在回读 `cl_drawhud` / `cl_draw_only_deathnotices`，恢复各项强制隐藏设置，游戏拒绝或无回执时报错。显示不再依赖必须先配置 session.lock；仍与录制共用全局资源锁。[CS2 变量转储](https://cs2.poggu.me/dumped-data/convar-list/)记录了 `cl_drawhud` 的 cheat 标志，其权限限制由游戏决定，不伪装成功；独立战队 HUD 通过 OBS 叠加。
- 跨回合第一条 GSI 过去直接返回，导致开局击杀被丢弃。现在按新回合计数和累计计数分别处理重置，不把上一回合的 round_kills 延续到下一回合。
- B 路冻结阶段过去没有有效时钟，开局击杀只能等 live 开始才准备。现在 A 路在本回合 freeze/live 边界测量实际回合时长，事件携带该数据，B 根据自己的冻结倒计时提前安排。未测得边界时不虚构回合时长。正常 freeze/live 过渡保留时钟推进证据，暂停/回档仍会拒绝录制。
- GSI 短暂断流超过 5 秒过去递增 epoch，使待录任务全部失效。现在仅重新建立检测基线；地图改变和真实回档才使旧时间线失效。倒计时仍须恢复推进才能录制。
- 调度轮询由 100ms 调至 50ms，回合任务提交余量由 100ms 改为 350ms。仅错过名义准备期限、但完整保护窗口尚未开始的事件仍允许尝试，实际 OBS 开始时间和镜头验证继续把关。
- 同一选手的新重叠击杀可追加到 COMMITTED / CAPTURING 录制；结束录制与追加操作在互斥锁下决策，避免尾部竞态。不会越过其他已承诺镜头，最长合并 30 秒。
- 选手镜头关闭自动导播，避免其在录制过程中切走。异常终止时等待 OBS 停止回执，减少后续任务反复收到“OBS 已在录制”。

## 本地历史证据

检查现有 `dist/ProjectReplay-0.1.0-linux-arm64/replay-data/state.json`，44 个任务中 31 个 READY；9 个任务因 `127.0.0.1:4455` 拒绝连接失败，2 个倒计时未推进 / 断流，1 个时间线暂停 / 跳转，1 个 OBS 已在录制。这说明后续大批漏录不能全部归因于间隔。实际 Linux OBS 必须在线，WebSocket 地址须与运行实例一致；此更新不擅自切换端口或重启 OBS。

## 清理范围

保留 state.json 中的 Config / Output 设置、战队图标、当前引用的两份转场和实例锁；清空 Replay media 内其余素材及下载残片、事件、任务、回放队列、运行日志和已登记的原始录制。不会删除用户 .dem、Steam / CS2、用户配置的工具和其他 OBS 录像。旧版未记录外部原始录像的归属，无法安全自动删除该部分。清理期间阻止新任务及上传写入。Linux 失败时 Windows 尚不删除；Windows 后续失败会报告 Linux 已清理，可幂等重试。

## 验证范围

回归覆盖：跨回合首杀、冻结期定位、正常阶段过渡、短暂断流与回档、准备期限边界、连续击杀追加和镜头预留、初始队伍/常规换边/加时换边、两端配置同步、清理保留配置及转场、节点忙时不清理本地、HUD 回读失败、OBS 源安装幂等性与缩放、浏览器 HUD 隐藏和文字安全。Go 全项目测试、竞态检测、go vet、Node 输出/HUD 测试以及三平台交叉构建用于验证。

此轮没有可用的真实 Windows CS2 + Linux OBS 双机直播环境；模拟服务通过不等于已完成现场整场比赛验收。GSI 仍是近似事件定位，单个 GSI 批量变化无法恢复每次击杀的精确时刻；不同选手重叠的两秒窗口仍需选取其中一个视角。
