# 云中继部署与配对（0.2.5）

## 软件与原局域网的关系

云中继是新增的可选连接模式。旧配置中没有 `connection_mode` 时继续使用原局域网模式，原 Linux 节点 URL、HTTP 指令、视频下载和启动脚本均保留。切回“局域网直连（原方案）”即可使用保存的节点 URL。两端应一起升级至 0.2.5，云中继使用同版本。

- Windows：`ProjectReplay-0.2.5-windows-amd64-portable.zip`。
- DGX Spark / ARM64 Linux：`ProjectReplay-0.2.5-linux-arm64.tar.gz`。
- x86-64 Linux：`ProjectReplay-0.2.5-linux-amd64.tar.gz`。
- 云服务器：按 CPU 架构使用 `ProjectReplay-Relay-0.2.5-linux-amd64.tar.gz` 或 `linux-arm64` 包；云端不安装 CS2、Steam 或 OBS。

升级只替换程序，保留原 `replay-data`。不要运行两个实例共用同一数据目录。

## 云服务器启动

云端只需要可访问的公网 IP，无需域名、反向代理或证书。两端主动通过 HTTP / WS 连接云端，云端无需访问两端局域网。直接 IP 模式的群组码、指令和视频传输不加密；需要加密时仍可使用 HTTPS / WSS（证书须覆盖所填写的 IP 或域名）。
1. 解压云端包。无需生成 `devices.json`，无需设备 Token；旧凭据文件不再读取。升级旧 systemd 服务时删除 `-credentials` 参数，使用本版本的服务示例。

2. 直接启动 IP 中继：

   ```sh
   ./replay-relay -listen :7790 -data ./relay-data -cache-gib 10
   ```

   在云服务器安全组及系统防火墙放行 TCP 7790。两端填写同一个公网 IP，例如 `203.0.113.10`（示例地址，请替换），程序自动保存为 `http://203.0.113.10:7790`。也可填写 `IP:端口` 或完整 HTTP URL；裸 IPv6 自动使用 7790，自定义端口写作 `[IPv6]:端口`。用 `http://公网IP:7790/healthz` 检查服务是否可达。

   已有 HTTPS 反向代理时，使用 `-listen 127.0.0.1:7790`，参考 `configs/Caddyfile.example`，并启用 WebSocket 转发。素材请求超时至少 6 分钟，上传请求体上限至少 1 MiB。

3. 也可使用已有证书直接提供 TLS，无需反向代理：

   ```sh
   ./replay-relay -listen :7790 -data ./relay-data -cache-gib 10 -tls-cert /path/fullchain.pem -tls-key /path/privkey.pem
   ```

   此时客户端填写 `https://你的域名:7790`，并放行该端口。程序不会自动申请或续签直接使用的证书。

4. 长期运行可参考 `configs/replay-relay.service`：创建独立系统用户 `replay-relay`；二进制放 `/opt/project-replay-relay/`；状态目录由 systemd 创建。按实际路径调整后安装、启用该服务。不要同时启动手工实例和系统服务。

`GET /healthz` 可作存活检查。维护时保留 `relay-data/nodes.json` ：该文件保存设备群组与配对关系。视频缓存是临时数据，云端重启会丢弃缓存，端侧保留的素材可重新上传。

## 两端设置

在“配置你的回放工作流”中选择“云中继”，分别填写：

| 字段 | 主机 | 录制机 |
|---|---|---|
| 云中继地址 | 相同的公网 IP 或 IP:端口 | 相同的公网 IP 或 IP:端口 |
| 群组码 | 例如 `0001` | 同样填写 `0001` |
| 设备名称 | 可识别的导播名称 | 可识别的录制机名称 |
| 开启自动配对 | 不适用 | 默认关闭，按需开启 |

群组码必须恰好四位 ASCII 数字，保留前导零；`0001` 与 `0002` 不可互相搜索或配对。设备 ID 由客户端自动生成并保存在数据目录，角色来自启动方式；无需手工配置设备 ID 或 Token。群组码是本模式唯一的接入约定，知道同组码的人可以发现同组设备。公网模式建议两端本地服务监听 `127.0.0.1:7788`；原局域网监听方式保持可用。OBS 与 NetCon 继续使用本机地址。

保存后，页面出现“云中继连接”面板：

- **手动配对**：主机搜索同组设备，选择录制机发起请求，录制机点击接受或拒绝。
- **自动配对**：录制机开启后，服务端立即匹配同组在线、未配对的主机，无需双方点击确认。多人同时空闲时，按设备 ID 排序选择，匹配操作在云端串行完成。
- **一对一保护**：已有配对不会被其他主机抢占；即使对方暂时离线，也保留原配对，防止重连时换机。
- **关闭自动配对**：已有配对保留；开关持久化，重启后保持。正在录制时先等待当前任务完成再调整。
- **解除配对**：停止原配对后续指令与视频访问。自动配对仍开启时，之后有设备重新接入可能再次配对；如需一直保持手动选择，请先关闭自动配对。
- **修改群组码**：重新连接云端后立即解除旧配对，旧配对标识不可再用于指令和视频请求。搜索列表随群组变化清空。
- **断线重连**：约每 3 秒重试；恢复原配对，不自动补执行离线指令。结果不确定的录制任务使用原任务 ID 查询，无法对账时沿用现有暂停保护。

配置中的原“Linux 节点 URL”不会被覆盖；中继模式下不会使用该地址。两端仍须配置同一比赛，地图来自各自 GSI，原游戏时间线与视角验证要求不变。

## GOTV 与视频

GOTV 地址和密码通过中继控制通道下发（HTTP 模式不加密），录制机直接连接比赛 GOTV。勾选自动发送后，首次配对或 GOTV 信息变化时发送一次；失败或结果不明时提示手工核验，避免盲目重试重复连接。云端不转发 GOTV 游戏广播，也不生成额外观战延迟。

视频采用主机拉取触发的缓存流程：节点报告素材 READY → 主机请求素材 → 云端通知录制机按 1 MiB 分块上传 → 云端校验大小及 SHA-256 → 主机通过 HTTP Range 下载 → 主机再次校验并原子落盘 → 加入可播库 → 确认后删除云端副本。

- 上传中断后由云端返回已有偏移，继续上传；下载中断保留 `.part` 并续传。云端重启后重新上传，但主机的已下载部分仍可用于 Range 续传。
- 控制消息与视频使用独立连接，录制机一次只上传一个片段；不在控制 WebSocket 中塞入视频。
- 面板显示上传字节进度、云端校验完成状态和连接状态，原任务列表继续显示回传/就绪/失败状态。
- 默认缓存配额 10 GiB，可用 `-cache-gib` 调整；未确认片段最长保留 24 小时，失效配对缓存定期清理。配额按素材总大小预留；磁盘写入失败不会返回成功。
- 上传等待最长 5 分钟，端侧素材请求最长 6 分钟，最多重试 3 次；带宽过低会明确失败，不将残缺文件标记为可播。
- 不增加实时画面预览、不转码、不改变 CS2/OBS 录制与 Windows 播出方式。

## 验证与上线边界

测试使用本机模拟云端、主机和录制机，覆盖同组自动与手动配对、跨组及伪造群组拒绝、已有配对不被抢占、配对代际失效、云端重启保留配对、分块续传、Range 下载、SHA-256、缓存确认删除、无需 Token和原局域网回归。

正式使用前需在你的云服务器上补做公网 IP 连通、实际带宽/延迟、长时间网络中断，以及真实 GOTV + CS2 + OBS 录制播出验收。当前交付不包含云资源购买、证书申请或在未知服务器上的部署。

实际页面检查已通过：默认仍选局域网；同组搜索→主机请求→录制机接受；解除后开启自动配对、两端自动显示已配对；群组改为 `0002` 后，`0001` 主机搜索不到录制机；设置页保留前导零且没有 Token 或设备 ID 输入项。检查使用隔离的本机实例和内置浏览器，未启动真实游戏或录制。
